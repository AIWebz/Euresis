# Euresis-LM — 690 B parameter configuration

Same architecture and code as the trained Euresis-LM (decoder-only transformer, `euresis/lm/model.py`), scaled up. The parameter count was computed by tracing the model's own `init_params` (`jax.eval_shape`, nothing allocated).

| Setting | Value |
|---|---|
| Parameters | **690,313,918,464** (690.31 B) |
| Layers | 169 |
| Model width d | 18,432 |
| Attention heads | 144 (head dim 128) |
| MLP width | 73,728 |
| Vocabulary | 65,536 |
| Context | 4,096 tokens |

## What it would take

| | |
|---|---|
| Weights (bfloat16) | 1.38 TB |
| Training state (weights, optimizer, gradients) | 11.0 TB → at least 139 × 80 GB GPUs just to hold it |
| Compute-optimal training data | 13.8 trillion tokens |
| Training compute | 5.7e+25 FLOP |
| Time | ≈ 4,589 GPU-years (H100-class, 40 % utilisation) ≈ 167 days on 10 000 GPUs |
| Serving it | ≈ 21 × 80 GB GPUs |

## Status

**Not trained, and not trainable here.** This machine has 4 CPU cores, 15 GB RAM, about 26 GB of free disk and no GPU; the weights alone would not fit on its disk. The text corpus Euresis has (≈ 200 k PubMed abstracts, tens of millions of tokens) is also about 10⁵–10⁶ × smaller than the ≈ 14 trillion tokens such a model needs.

Smoke test of the identical code path at tiny scale: 584,640 parameters, logits (2, 16, 512), finite = True.

Practical route to a model of this size: use an existing frontier model through its API as Euresis' reasoning core (Euresis already supports the Claude API — set `ANTHROPIC_API_KEY`).
